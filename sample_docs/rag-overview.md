# RAG (Retrieval-Augmented Generation) 概觀

## 什麼是 RAG？

RAG 是一種讓 LLM 在回答問題之前，先去搜尋相關文件，用搜到的內容當參考資料回答的技術。這樣可以大幅減少 LLM 的幻覺問題。

## 核心流程

1. **文件匯入（Ingest）**：把文件切成小塊，轉成向量，存進向量資料庫
2. **問答（Query）**：用戶問問題 → 搜出最相關的文件片段 → 餵給 LLM 生成回答

## 為什麼需要 RAG？

- LLM 的訓練資料有截止日期，無法回答最新的問題
- LLM 不知道你的內部文件內容
- 直接問 LLM 可能會得到看似正確但實際上是編造的回答（幻覺）

## RAG vs Fine-tuning

| | RAG | Fine-tuning |
|--|-----|-------------|
| 更新知識 | 換文件就好 | 要重新訓練 |
| 成本 | 低（只需向量 DB） | 高（需要 GPU 訓練） |
| 引用來源 | 可以標註 | 無法標註 |
| 適合場景 | 知識庫問答 | 風格/格式調整 |
