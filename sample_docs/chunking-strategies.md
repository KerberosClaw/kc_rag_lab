# 文件切塊策略

## 為什麼要切塊？

Embedding model 有 token 上限，而且太長的文件轉成向量會稀釋語意，導致搜尋不精準。

## 常見策略

### 固定長度切塊

每 N 個字切一刀，簡單但會切斷句子。

### 按段落切塊

用空行或句號當分隔點，不會切斷句子但 chunk 大小差異大。

### 按 Heading 切塊

用 Markdown 的 `#`、`##`、`###` 當分隔點，保留語意完整性。適合有結構的技術文件。

### 語意切塊（Semantic Chunking）

用 embedding 判斷語意轉折點再切，效果最好但最慢。

## Overlap（重疊）

相鄰 chunk 之間保留一些重疊文字，避免答案被切斷。通常 50-100 字。

## Chunk 大小的 Trade-off

- **太大（>1000 字）**：向量語意被稀釋，搜尋不精準
- **太小（<100 字）**：缺少上下文，LLM 看不懂
- **建議值：200-500 字**
